① 완료된 기능 — 코드로 구현되고 테스트를 통과함

전략 엔진 3종 완료

strategies/mean_reversion·breakout·trend_following.py

자산 5개에 전략 3개를 배분: SPY·QQQ = 평균 회귀(이동평균 밴드), BTC = 돌파(거래량 동반 고저 이탈), GLD·USO = 추세 추종(50/200 EMA 교차).

왜 필요? 시장마다 성격이 달라서, 한 규칙을 모두에 쓰면 한쪽이 계속 손해를 본다.

리스크 관리 완료

risk/manager.py

거래당 위험 1%(손절 거리로 수량 결정), ATR 기반 변동성 사이징, 상관 필터(SPY·QQQ 롱이면 BTC 롱 차단), 트레일링 스톱.

왜 필요? 봇의 진짜 가치는 '수익'보다 '터지지 않는 것'. 이 모듈이 계좌를 지킨다.

실계좌 3중 잠금 완료

broker.py · resolve_mode()

기본값은 무조건 모의. 실계좌는 ①ALPACA_PAPER=false ②확인문구 ③--live 플래그가 동시에 있어야만 열림. 하나라도 없으면 자동으로 모의로 강등.

왜 필요? 실수로 진짜 돈이 나가는 사고를 원천 차단. 전용 테스트로 8가지 조합 검증됨.

포트폴리오 상태 보존 완료

portfolio.py

잔고 최고점(HWM), STOPPED 상태, 처리한 신호를 파일에 저장. 껐다 켜도 정지 기준·중복 방지가 유지됨.

왜 필요? 재시작 때마다 기준이 초기화되면 10% 정지장치가 무력해진다.

10% 서킷 브레이커 완료

risk/manager.py · portfolio.py

고점 대비 10% 하락 시 신규 주문 차단·전량 정리·STOPPED. 사람이 resume 하기 전까지 유지.

왜 필요? 감정이 개입할 틈을 코드가 막는다. 최악의 손실을 상한선으로 묶는다.

백테스트 엔진 완료

backtest.py

신호는 해당 봉 종가로 판단하되 체결은 다음 봉 시가로(미래참조 방지). 수수료·슬리피지 반영. 승률·손익비·MDD·샤프·총수익 산출.

왜 필요? 과거로 규칙의 구멍을 미리 찾는다. 누수 방지가 핵심.

벤치마크 우위 판정 완료

benchmark.py

전략이 Buy&Hold와 무작위 진입(리스크 관리 동일)을 둘 다 이기는지 판정. 무작위 분포의 상위 5% 밖이어야 '우위 근거 있음'.

왜 필요? 수익이 전략 덕인지 리스크 관리 덕인지 가른다. 실계좌 전 필수 관문.

로컬 대시보드 완료

dashboard.py

봇의 로컬 파일을 읽어 브라우저에 상황판 표시(15초 자동 새로고침). 자산곡선·낙폭·자산별 손익/승률·거래비중 차트 5종 + 리스크 신호.

왜 필요? 한눈에 상태 파악. 인터넷/커넥터 없이 로컬만으로 동작.

아침·저녁 리포트 완료

report.py

보유 포지션·손익·리스크 플래그를 요약. 기본은 dry-run(콘솔 미리보기), 토큰 없으면 오류 대신 미리보기.

왜 필요? '화면 0시간' 목표의 핵심. 하루 두 번 요약만 확인.

CLI + 테스트 13종 완료

main.py · tests/

backtest·benchmark·paper·live·status·stop·resume 명령. 리스크·3중잠금·미래참조 방지에 대한 자동 테스트 전부 통과.

왜 필요? 안전장치가 '있다'가 아니라 '작동한다'를 기계가 증명.

② 부분 구현 / 미구현 — 실거래로 가려면 남은 것

실데이터 연결 차단

.env · data.py

지금은 Alpaca 키가 없어 합성(가짜) 데이터로 폴백 중. 모든 백테스트·벤치마크 결과가 무의미한 상태.

선행조건: Alpaca 모의계좌 가입 후 API 키를 .env에 입력(무료, 5~10분). 사용자 작업.

실제 주문 실행 부분

broker.py · main.py (paper/live)

현재 paper --once / live 는 모드 판정·안전 배너까지만 구현. Alpaca에 실제 주문을 넣고 체결을 받아오는 연결부는 골격만 있음.

왜 나중? 2주 모의 검증 전에는 주문 루프를 켜지 않는 게 원칙(가이드 방침).

연속 감시 루프 예정

main.py

전략별 주기로 시세를 확인하며 계속 도는 루프, API 끊김·휴장 처리. 현재는 --once(1회) 골격만.

왜 나중? 주문 실행이 검증된 뒤 설계하는 게 안전.

백테스트 내 손절 체결 부분

backtest.py

진입 시 ATR 손절가는 계산하지만, 백테스트 루프가 봉 중간 손절 도달을 체결로 반영하지 않음(전략 청산 신호로만 종료). 결과가 실제보다 낙관적일 수 있음.

개선 필요: 손절 히트 체결을 백테스트에 넣으면 신뢰도가 올라감.

워크포워드 검증 예정

(신규)

앞 기간으로 파라미터를 정하고 '보지 않은' 뒷 기간으로만 평가. 과최적화를 걸러내는 2차 관문.

순서: 벤치마크에서 우위 신호가 난 자산만 여기로 넘긴다.

자동 중단 기준(kill-switch) 강화 예정

risk/manager.py 확장

"실전 낙폭이 백테스트 MDD의 1.5배 초과", "최근 20거래 승률이 기대치 절반 이하" 등 사전 정의된 중단 규칙을 코드화.

왜 필요? 실전이 백테스트에서 벗어나면 감정 개입 없이 멈추게.

텔레그램 실제 전송 부분

report.py

메시지 생성·dry-run 미리보기는 완료. 봇 토큰/Chat ID 발급 후 실제 전송은 사용자 설정 필요.

선행조건: BotFather에서 봇 생성 + Chat ID 확인.

예약·24시간 배포 예정

Windows 작업 스케줄러 / VPS

리포트 자동 발송 예약, 봇 24시간 가동(VPS), 죽어도 재시작. 리포트만 예약하고 주문 루프는 검증 후 별도.

비용: VPS 월 5~10달러. 모의 단계까지는 내 PC로 충분.

④ 비목표 & 한계 — 이번엔 안 하는 것 (명확히)

  • 한국 주식은 대상 아님. Alpaca는 미국 주식·ETF·(일부)코인만 지원. 한국 주식은 국내 증권사 API가 별도로 필요하다.
  • 선물·외환 없음. 금·원유도 실물 선물이 아니라 ETF(GLD·USO)로 대체.
  • '월 400만원' 보장 없음. 그건 한 사람의 사례일 뿐. 이 기획의 목표는 수익이 아니라 '검증 통과'다.
  • 고빈도·초단타 아님. 15분~4시간봉 기준. 체결 지연·시장 충격을 다투는 영역은 범위 밖.
  • 성능 한계. 백테스트/벤치마크가 데이터가 길면 느리다(향후 지표 사전계산으로 개선 여지).

⑥ 지금 필요한 결정

다음 한 걸음은 P1 — Alpaca 키 연결입니다. 이게 돼야 지금까지 만든 백테스트·벤치마크가 비로소 '진짜 판정'을 냅니다. 그다음은 판정 결과에 달렸습니다: 우위 근거가 있으면 워크포워드로 넘기고, 없으면 여기서 멈추거나 전략을 다시 설계합니다. 즉, 키 연결 → 벤치마크 판정이 이 프로젝트의 진짜 분기점입니다.
이 문서는 제품 기획 관점의 현황 정리이며 투자 자문이 아닙니다. 매매에는 원금 손실 위험이 따르고, 판단과 책임은 본인에게 있습니다.
